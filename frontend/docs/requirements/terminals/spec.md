# 端末管理

## 概要

テスト対象の端末をIPアドレスで登録・管理する画面。
端末ごとに自動監視のON/OFFを切り替え、オンライン状態を把握する。

## 画面構成

```
┌─────────────────────────────────────┐
│ 端末管理  オンライン X/Y台  監視中 Z台  │  ← ヘッダー
├─────────────────────────────────────┤
│ [端末を追加]  [一括削除]              │  ← ツールバー
├────┬──────┬──────┬────┬──────┬────┤
│    │ 端末名 │IPアドレス│ 状態 │自動監視│ 操作 │  ← テーブルヘッダー（クリックでソート）
├────┼──────┼──────┼────┼──────┼────┤
│ ●  │端末-01 │192.168.1.101│オンライン│監視中│ ✏️ 🗑️ │
│ ○  │端末-02 │192.168.1.102│オフライン│停止中│ ✏️ 🗑️ │
└────┴──────┴──────┴────┴──────┴────┘
```

## 機能一覧

### 端末一覧表示
- 登録済み端末を一覧表示する
- 表示項目：状態ドット・端末名・IPアドレス・オンライン状態・自動監視スイッチ・操作ボタン
- ヘッダー（端末名・IPアドレス・状態・自動監視）をクリックするとソートできる
- 同じ列を再クリックで昇順/降順を切り替える
- ヘッダーに統計を表示する（オンライン台数 / 総台数、監視中台数）
- 端末が0件のとき「端末を追加してください」と表示する

### 端末追加
- 「端末を追加」ボタンでダイアログを開く
- **1件追加**と**一括追加**をタブで切り替える
- ダイアログは常に「1件追加」タブで開く

#### 1件追加
- 端末名（省略可。省略時はIPアドレスが端末名になる）
- IPアドレスをオクテットごとに4つの入力欄で入力する
- 既存端末が1件以上ある場合、第1〜第3オクテットを自動入力する
- 3桁入力すると次のオクテットにフォーカスが移動する
- 重複IPはエラーメッセージを表示して追加できない
- 無効な値（範囲外・数値以外・先頭ゼロ）はエラーメッセージで誘導する

#### 一括追加
- IPプレフィックス（第1〜第3オクテット）をオクテットごとに入力する
- 開始番号・終了番号（第4オクテットの範囲）を入力する
- 端末名プレフィックス（省略可。省略時はIPアドレスが端末名になる）
- 追加予定の端末をプレビュー表示する
- 既存IPと重複するものは「重複」バッジで表示し、追加対象から除外する
- プレフィックス・番号それぞれにバリデーションエラーを表示する

### 端末削除

#### 個別削除
- 各行の削除ボタン（🗑️）をクリックする
- 確認ダイアログを表示してから削除する

#### 一括削除
- 「一括削除」ボタンでダイアログを開く
- チェックボックスで複数の端末を選択して削除する
- 「すべて選択」行・各端末行はテキストをクリックしてもチェックが入る
- 削除ボタンに選択件数を表示する（例：削除 (3)）
- 環境を切り替える際に全端末を一括削除するユースケースを想定する

### 端末名変更
- 各行の編集ボタン（✏️）をクリックしてダイアログを開く
- 端末名を変更できる（IPアドレスは変更不可）
- 端末名が空のまま変更ボタンを押せない

### 日付選択
- 各端末行に選択中の日付を表示する
- カレンダーUIで日付を選択できる
- **1端末につき1日付のみ**選択可能
- 自動監視ON中は日付を変更できない（表示のみ）
- 未選択時は「---」などで未選択状態を表示する

### 自動監視切り替え
- 各行のスイッチでON/OFFを切り替える
- ON：「監視中」、OFF：「停止中」と表示する

## API・状態管理の方針

### 基本方針
- **フロントの操作結果が正**。操作時にAPIを叩き、成功を前提にフロントを更新する
- ポーリングはオンライン状態の取得のみに使用する（監視ON/OFFは含めない）
- 監視ON/OFFはユーザーが操作したときのみAPIを叩く

### ポーリング
- 一定間隔（例：5〜10秒）でオンライン状態を取得する
- `GET /api/terminals/status` でオンライン状態のみを返す
- フロントはオンライン状態をポーリング結果で上書きする

### 起動時のヘルスチェック
- アプリ起動時に `GET /api/health` でバックエンドへの接続を確認する
- 接続できない場合は「バックエンドに接続できません」とエラーを表示する
- 接続できるまで操作を受け付けない
- ポートバッティング等の起動失敗を早期に検出するのが目的

### 起動時シーケンス

```
1. ヘルスチェック（GET /api/health）
2. 端末リスト取得（GET /api/terminals）
   - 端末リスト・監視状態・日付をバックエンドから復元
   - 端末情報はバックエンドのJSONファイルで永続化
3. ステータスチェック（GET /api/terminals/status）※監視ONの端末がある場合
   - ping でオンライン確認
   - net time で端末日付を取得（失敗時はPC日付）
4. 採取復元 ※監視ONの端末がある場合
```

- localstorageは使わない。状態はすべてバックエンドで永続化する
- ステータスチェックと採取復元は必ずこの順番で実行する
